# 平台环境

适用于通过开放平台运行的业务任务。按[环境](../SKILL.md#环境)选择正式或测试环境；应用固定两类平台入口，Skill不维护域名。本参考说明账号准备及新旧入口范围。

## 账号准备

登录只使用profile与environment。用户提供的网页只用于定位浏览器阶段；应用负责选入口和校验旧记录，本人完成浏览器验证。应用返回入口或记录不匹配时按[登录定位](login.md#未完成时定位)恢复。

业务请求继续由Gateway转发，登录入口与业务转发分别由应用及服务端管理。

1. 用户未明说环境时选择正式prod；明确指定测试或续办已明确为测试的原任务时选择stg。只有测试账号、旧默认上下文或清单示例为STG，不改变新任务的默认选择；正式环境不可用时保留原任务并说明缺项。
2. 读取 `profiles`，只选择environment和本人均匹配的记录。无匹配记录时 Agent 选择未占用的本地记录名，例如 `work-prod`；保留原记录，记录名由 Agent 管理，不要求用户提供，也不预填其他人的身份。
3. 按[浏览器登录](login.md)运行已固定的平台参数并保持进程。验证成功后使用返回的稳定本人；仅需默认上下文时再运行 `context use --profile <该记录> --environment <原环境>`。
4. 按当前环境解析业务别名，以真实 `contract.environment`、`systemId`、读写性质、请求／响应 Schema 和数据范围核对，再使用返回的版本及对象。

## 固定入口与实际权限

login 由应用按 prod／stg 选择固定入口。新任务未指定环境默认 prod；原任务恢复沿用已明确环境及本人记录。

缺少平台账号时先完成本人登录，再解析接口。登录、接口发布、员工许可与实际业务调用分别验证。业务清单中的环境要求不替代当前用户的任务环境。

旧员工设备资料保持原位，当前 CLI 不读取、迁移、恢复或自动清理。
