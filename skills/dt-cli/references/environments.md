# 平台环境

适用于通过开放平台运行的业务任务。按[环境](../SKILL.md#环境)选择正式或测试环境；应用固定两类平台入口，Skill不维护域名。本参考说明账号准备及新旧入口范围。

## 账号准备

登录只使用profile与environment。用户提供的网页只用于定位浏览器阶段；应用负责选入口和校验旧记录，本人完成浏览器验证。应用返回入口或记录不匹配时按[登录定位](login.md#未完成时定位)恢复。

业务请求继续由Gateway转发，登录入口与业务转发分别由应用及服务端管理。

1. 用户未明说环境时选择正式prod；明确指定测试或续办已明确为测试的原任务时选择stg。只有测试账号、旧默认上下文或清单示例为STG，不改变新任务的默认选择；正式环境不可用时保留原任务并说明缺项。
2. 读取 `platform profiles`，只选择environment和本人均匹配的记录。无匹配记录时 Agent 选择未占用的本地记录名，例如 `work-prod`；保留原记录，记录名由 Agent 管理，不要求用户提供，也不预填其他人的身份。
3. 按[浏览器登录](login.md)运行已固定的平台参数并保持进程。验证成功后使用返回的稳定本人；仅需默认上下文时再运行 `platform context use --profile <该记录> --environment <原环境>`。
4. 按当前环境解析业务别名，以真实 `contract.environment`、`systemId`、读写性质、请求／响应 Schema 和数据范围核对，再使用返回的版本及对象。

## 新旧入口范围

`platform login` 由应用按prod／stg选择固定入口，未传环境时默认prod；不依赖旧个人／governed的内置环境清单。离线 `doctor` 的 `environments=["stg"]`、旧 `profiles list` 或 `tasks list` 的 `like.send / PROFILE_REQUIRED`，只描述旧入口，不能证明正式平台未配置或新平台不能运行。

平台没有账号时，缺项是本机本人登录。Agent先固定平台参数并发起登录，成功后解析接口；不能将缺少登录改写成接口未发布、全组织未开通或必须换终端。

业务清单声明的环境只是该环境的要求：先选择匹配环境的一组；其他环境核对等效业务约束，接口版本编号不跨环境比较。接口发布、员工许可、本人登录与实际业务调用分别验证，不以配置或一次解析成功代替业务结果。
