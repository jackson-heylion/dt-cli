# 浏览器登录

缺少账号、认证到期或用户明确要求登录时使用。按[环境](../SKILL.md#环境)确定prod或stg，由应用选择平台入口；记录名由Agent选未占用的本地名称。命令准备见[平台调用](platform.md#准备与发现)。

## 发起并继续

1. 确定任务环境后，使用profile与environment发起登录，应用负责入口选择。提示：“请在浏览器确认登录，确认后我会继续。”`login` 默认自动打开浏览器，不要求交互终端。需要改用手动打开方式时，可在新一轮使用 `--no-browser`。本人验证在系统浏览器完成。
2. 使用可保留子进程的工具会话，首次尽快返回进度，保存会话标识，随后读取同一会话的标准错误与退出状态。单次读取上限300秒，按宿主限制或进度需要可缩短；命令总超时至少1800秒，覆盖CLI的1500秒回调期限和后续换码、检查及保存。工具返回等待状态时原进程仍在运行，继续读取该会话；明确退出后才结束等待。结合 `processId` 与 `callbackAddress` 核对原进程，保持同一个登录进程直至最终结果。若工具只能整段阻塞，发起前先提示；不能把后台启动成功当作登录完成。
3. 收到等待进度时及时提醒本人查看浏览器。约30秒仍无回调且页面状态未知时，询问“是否看到登录页”；本人已确认看到页面或完成验证时，直接按下节核对所在页面与回调，不重复询问。有明确页面错误时记录页面阶段和脱敏错误，继续等待需要本人操作的原进程。
4. 同时取得退出码0和 `ok=true` 后自动继续原任务；已有分页任务续原检查点，写入结果未知仍只核对原意图。成功页、窗口关闭或 `callback_received` 尚不能替代最终结果。

成功结果若附 `warning=previous_credential_cleanup_failed`，告知使用员工旧凭证清理未完成，仍可沿已保存的新会话继续。

## 进度含义

| 实际证据 | 可得结论与动作 |
| --- | --- |
| `checking_network` | CLI使用随后换码的客户端检查匿名平台接口；尚未请求打开浏览器 |
| `opening_browser` | 正在请求系统打开；窗口尚未确认 |
| `waiting_for_browser` / `browserLaunch=requested` | 打开调用没有报错；窗口显示、页面加载与验证结果仍待确认 |
| `open_browser_failed` / `browserLaunch=failed` | 自动打开调用失败；进程仍在等待，可按下节使用本次链接 |
| `browserLaunch=disabled` | 此次参数禁止自动打开；按用户选定的自行打开流程处理 |
| `callback_connected` / `callbackStatus=connected` | 本机端口收到连接。空连接、无关请求或未发完的请求会被略过，原等待期限继续计算 |
| `callback_received` / `callbackStatus=validated` | 回调通过校验；继续等待换码、保存及最终结果 |
| `exchanging_code` | CLI 开始向平台换码；结果仍待确认 |
| `TIMEOUT` / `timed_out` | 本次期限内没有取得有效授权回调；原因仍须结合窗口、页面和端口事实判断 |

各阶段按实际事件与最终结果判断，缺失字段记为未知。`waitSeconds` 是CLI回调期限，`pollMaxSeconds` 和 `commandTimeoutSeconds` 是工具读取上限与总超时建议下限；后两者不能代替实际工具配置。进度仅写标准错误，标准输出留给最终信封；不凭 `waiting_for_browser`、放开沙箱或单次超时宣称页面已打开、排除权限问题或归因于本人未操作。

## 未完成时定位

- **登录保存待核对**：`meta.loginSave=unconfirmed` 时，按恢复动作使用原本地账号记录对应的 `check` 或 `manage check`。核对通过后再续办，保留原本人、环境和用途。若 `meta.loginSave=not_saved`，分别报告原保存错误、`remoteRevocation` 和 `credentialCleanup`。两种情况均不重放授权码或自动重登。

- **匿名网络检查或换码失败**：先说明业务能否继续，并指向企业网络支持。排障时读取 `loginStage`、`reason` 及已有 HTTP 状态。`proxy_connect_failed` 核对代理与目标域名规则，`dns_resolution_failed` 核对目标解析，`tls_failed` 核对证书、系统时间与代理设置。保留证书校验。`authorizationCodeStatus=unknown` 表示换码结果待确认，网络恢复后或本人主动重试时用新的授权链接。
- **回调校验失败**：`callback_validation` 在换码之前发生，收到连接无法确定浏览器行为或授权码状态。保留错误阶段和退出码，原因未知时如实记录。原尝试结束后需要再试，可用 `--no-browser` 发起新一轮，在同机 Chrome 等浏览器手动打开新链接。
- **应用拒绝旧地址或账号记录**：`PLATFORM_ORIGIN_MISMATCH` 时移除旧命令中的地址参数，按原环境重建一次登录；`PLATFORM_PROFILE_ORIGIN_MISMATCH` 时保留旧记录，选择未占用的本地记录名登录同一环境。应用尚未打开浏览器时先处理该错误，本人无需另找域名。
- **未看到浏览器**：优先用宿主提供的本机打开能力打开当前进程日志中的同一 HTTPS 授权入口；没有此能力时让本人在同机浏览器打开该入口。先确认是否显示登录页，保持原进程。只在这次操作中使用链接，不把授权参数写入报告；不要打开 `127.0.0.1` 回调地址，也不自行拼接或修改授权链接。
- **看到页面但无法登录**：记录卡在页面加载、员工验证还是授权确认，保留实际错误。确定问题已消除或用户主动重试后再发起一次；超时和 `retryable=true` 本身不授权循环重登或连续弹窗。
- **页面已完成验证但 CLI 仍在等**：先确认是否仍待 CLI 授权确认，身份验证完成仍须取得 CLI 最终成功信封。核对该次实际回调端口及 PID，确认原进程仍活着；在同一宿主检查监听，只观察端口与进程，不向回调端口发送测试请求。沙箱视角查不到监听不能证明没有监听；同机也未必代表网络隔离可互通。核对浏览器重定向错误、实际执行方式和本机回环访问限制，保留未知原因。
- **同时发生存储错误**：按[本地存储恢复](recovery.md#本地存储故障)定位，并记录检查是在沙箱还是宿主执行。配置写入成功、宿主检查通过与原沙箱可用分别核对；文件许可不能替代浏览器或网络验证。

超时或取消后原进程及本机回调已经结束，原链接不再用于登录。原因未变时停止本次尝试；此前两次超时是历史结果，不是永久禁止Agent登录。用户在新版继续原任务或明确重试时，按已确认入口发起一次并及时核对页面；本人在浏览器验证不等于本人手动执行命令。确需本人终端执行时交付当前 shell 可复制的完整命令，PowerShell 调用已引用的程序路径需要 `&`。以工具明确无法保持本机进程、打开入口或收到当前权限拦截为依据，不能仅凭非交互输入或历史超时转交手工执行。

日常只告诉本人业务是否继续以及当前需要做的事。例如“查询还没开始，请在浏览器点‘确认登录’。”主动排障时再给阶段、退出码与已确认事实。授权链接仅在当前登录操作中使用，报告中省去授权链接、授权码和凭证。
