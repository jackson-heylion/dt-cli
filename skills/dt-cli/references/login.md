# 浏览器登录

缺少账号、认证到期或用户明确要求登录时使用。按[环境](../SKILL.md#环境)确定prod或stg，由应用选择平台入口；记录名由Agent选未占用的本地名称。新平台命令见[平台准备](platform.md#准备与发现)，旧本人登录见[首次使用](first-use.md#选择账号)。

## 发起并继续

1. 确定任务环境后，使用profile与environment发起登录，应用负责入口选择。开始前提示：“需要登录，我正在打开浏览器。请完成扫码或密码验证，成功后我会自动继续查询。”`platform login` 默认自动打开浏览器，不要求交互终端；正常准备使用默认行为，`--no-browser` 仅用于用户明确选择自行打开链接的流程。本人验证在系统浏览器完成。
2. 使用本地工具的可保持会话模式，首次尽快返回进度，随后分段读取标准错误与退出状态；单次等待控制在60秒内。保留同一个登录进程，进程退出才结束等待。若工具只能整段阻塞，发起前先提示；不能把后台启动成功当作登录完成。
3. 收到等待进度时及时提醒本人查看浏览器。约30秒仍无回调且页面状态未知时，询问“是否看到登录页”；本人已确认看到页面或完成验证时，直接按下节核对所在页面与回调，不重复询问。有明确页面错误时记录页面阶段和脱敏错误，继续等待需要本人操作的原进程。
4. 同时取得退出码0和 `ok=true` 后自动继续原任务；已有分页任务续原检查点，写入结果未知仍只核对原意图。成功页、窗口关闭或 `callback_received` 尚不能替代最终结果。

## 进度含义

| 实际证据 | 可得结论与动作 |
| --- | --- |
| `opening_browser` | 正在请求系统打开；窗口尚未确认 |
| `waiting_for_browser` / `browserLaunch=requested` | 打开调用没有报错；窗口显示、页面加载与验证结果仍待确认 |
| `open_browser_failed` / `browserLaunch=failed` | 自动打开调用失败；进程仍在等待，可按下节使用本次链接 |
| `browserLaunch=disabled` | 此次参数禁止自动打开；按用户选定的自行打开流程处理 |
| `callback_connected` / `callbackStatus=connected` | 本机端口收到连接；还未证明是完整有效的授权回调 |
| `callback_received` / `callbackStatus=validated` | 回调通过校验；继续等待换码、保存及最终结果 |
| `TIMEOUT` / `timed_out` | 本次期限内没有取得有效授权回调；原因仍须结合窗口、页面和端口事实判断 |

这些附加字段仅在支持它们的 CLI 中提供；0.7.0 等旧版按实际 stage 与最终结果判断，缺失字段记为未知。进度仅写标准错误，标准输出留给最终信封；不凭 `waiting_for_browser`、放开沙箱或单次超时宣称页面已打开、排除权限问题或归因于本人未操作。

## 未完成时定位

- **应用拒绝旧地址或账号记录**：`PLATFORM_ORIGIN_MISMATCH` 时移除旧命令中的地址参数，按原环境重建一次登录；`PLATFORM_PROFILE_ORIGIN_MISMATCH` 时保留旧记录，选择未占用的本地记录名登录同一环境。应用尚未打开浏览器时先处理该错误，本人无需另找域名。
- **未看到浏览器**：优先用宿主提供的本机打开能力打开当前进程日志中的同一 HTTPS 授权入口；没有此能力时让本人在同机浏览器打开该入口。先确认是否显示登录页，保持原进程。只在这次操作中使用链接，不把授权参数写入报告；不要打开 `127.0.0.1` 回调地址，也不自行拼接或修改授权链接。
- **看到页面但无法登录**：记录卡在页面加载、员工验证还是授权确认，保留实际错误。确定问题已消除或用户主动重试后再发起一次；超时和 `retryable=true` 本身不授权循环重登或连续弹窗。
- **页面已完成验证但 CLI 仍在等**：先确认是否仍待 CLI 授权确认，身份验证完成仍须取得 CLI 最终成功信封。核对该次实际回调端口及 PID，确认原进程仍活着；在同一宿主检查监听，只观察端口与进程，不向回调端口发送测试请求。沙箱视角查不到监听不能证明没有监听；同机也未必代表网络隔离可互通。核对浏览器重定向错误、实际执行方式和本机回环访问限制，保留未知原因。
- **同时发生存储错误**：按[本地存储恢复](recovery.md#本地存储故障)定位，并记录检查是在沙箱还是宿主执行。配置写入成功、宿主检查通过与原沙箱可用分别核对；文件许可不能替代浏览器或网络验证。

超时或取消后原进程及本机回调已经结束，原链接不再用于登录。原因未变时停止本次尝试；此前两次超时是历史结果，不是永久禁止Agent登录。用户在新版继续原任务或明确重试时，按已确认入口发起一次并及时核对页面；本人在浏览器验证不等于本人手动执行命令。确需本人终端执行时交付当前 shell 可复制的完整命令，PowerShell 调用已引用的程序路径需要 `&`。以工具明确无法保持本机进程、打开入口或收到当前权限拦截为依据，不能仅凭非交互输入或历史超时转交手工执行。

阻塞回复只说：登录尚未完成、已确认到哪一步、仍未知什么，以及当前需要的一项操作。示例：“还没收到登录回调，查询暂未开始。现在需要确认浏览器是否显示登录页；本次超时原因尚未确定。”
