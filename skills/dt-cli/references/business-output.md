# 业务表达

进度、操作提示、草稿和结果用员工熟悉的中文。先说查到什么、办到哪一步，再给必要的范围、限制和本人需做的动作。固定名称、业务编码及原始法律文本按需保留。

| 数据 | 业务表达 |
| --- | --- |
| 人员、门店、品项、仓库 | 名称；辨识需要时补业务编码 |
| 空值 | 未提供；不推断未配置或无限制 |
| 确定的零 | 0，保留单位 |
| 布尔状态 | 按已核实含义写可订货／不可订货等 |
| 无匹配记录 | 本次条件下未查到，不推断业务未发生 |
| 数据不足 | 暂无法计算，说明缺少的数据，不显示为0% |
| 部分完成 | 说明已覆盖和未覆盖范围 |
| 已确认写入成功 | 说明办了什么、涉及谁或什么对象 |
| 写入结果未知 | 发送结果尚未确认，按原记录核对 |

字段含义、单位、精度和币种须有依据。表内已有数值无需在表后复述。命令、接口编号、内部状态和日志留在执行记录，在主动排障、用户索要或本人确需执行命令时提供所需部分。

例如“查到 5 条订货配置”“这个门店今天没有查到匹配记录”“已给李明发送点赞”。需要本人操作时用“请在浏览器确认登录，确认后我会继续”。结果待核对时用“还不能确认点赞是否已发送，我会核对原记录”。

空结果不能证明预测未运行、未回写或员工操作异常；原因需要本次对象与日期的独立证据。缺证据写“暂无法判断原因”。

用户问耗时时，只使用实际日志区分准备、取数、重复请求、参数修正及整理。未测量部分如实说明，不把未包装的间隙全部归为模型或网络，也不保证下次耗时。专门计时见[测试记录](testing.md)。
