# 沙盒执行与客户端授权

业务读取也可能续期、写缓存或替换本地文件。复用已批准的绝对 launcher 和执行环境，遵守宿主授权；Skill 不关闭客户端安全策略。

首次文件访问被拒绝或 CLI 返回存储错误，立即结束本次任务。使用原错误的 code、area、stage、reason、osCode 报告已知事实；EPERM 不能单独证明沙盒、文件属性或系统权限是根因。

不自动运行 doctor、重试登录或其他接口，不检查/修改凭证内容、权限和扩展属性，不创建测试文件，不清理、搬移或链接凭证目录，不通过换 shell 或请求放开沙盒继续试探。只保留原账号、原ID和已有结果。

交付已有的原失败调用：使用已确认 launcher、profile、合同与参数，给出一条可复制的准确命令，供权限恢复后或本机终端执行。缺少中心ID时只交付原中心查询，不能拼出未验证的后续命令、递归取首个ID或新增 Python 依赖。不要为完善交付命令继续调用 CLI 或网络。

回复：“本地保存失败，本次未查到结果。错误：<实际 code/area/stage/osCode>。请由客户端或终端支持恢复访问后再执行下面的命令。”如已有部分结果，说明哪部分已取得、哪部分未完成；写入结果未知时保留原 intent/runId，不提供重新派发命令。

只有用户或宿主明确确认访问权限已恢复，才重试原操作一次。用户另行明确要求排障时，可以执行 CLI 的显式诊断；普通查询失败不转成排障任务。不保证独立终端一定成功，也不宣称未经核对的凭证还原或无数据丢失。
