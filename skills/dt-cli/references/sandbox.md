# 沙盒执行与客户端授权

## 需要哪些本地能力

业务读取也可能自动续期、保存目录缓存及恢复记录。CLI 需要在自己的配置目录创建、写入、原子替换、删除自己管理的文件，并使用安装目录中的受管程序。首次登录还需要本机系统浏览器和 loopback 回调；IAM 及固定发行入口需要网络访问。业务只读不等于本地文件只读。

从宿主工具返回的权限状态判断执行条件，复用已确认的绝对 launcher。安装与后续登录、查询、诊断使用同一个允许的本地执行环境；bootstrap 在沙盒外成功不能证明沙盒内的查询也能保存凭证。无 TTY 不代表远端沙盒，EPERM 也不能单独证明沙盒或系统权限是根因。

## 减少重复弹窗

1. 使用原生 CLI 命令和参数数组。每次命令只执行原任务需要的操作；shell 不自行进入 credentials 目录或运行 touch、rm、mv、chmod、测试 rename、全目录清理等凭证实验。CLI 的 doctor --storage 已覆盖必要文件能力，不追加 shell 探针。
2. 有效宿主授权在其范围内复用，保持绝对 launcher 路径与调用形式稳定。客户端提供用户可选择的会话授权、可复用命令规则或目录授权时，只提交本任务必需的范围：已验证 launcher、本地配置和安装目录、所需网络与登录回调。由用户决定是否保存，Agent 不能替用户选择“始终允许”。不请求全局 shell、全盘删除或关闭安全中心。
3. 宿主要求授权时，提交具体 CLI 命令和用途；一次说明实际需要的本地读写、原子替换及清理能力。使用宿主正式支持的授权入口。业务指令的授权不能代替宿主审批；用户拒绝后停止依赖该权限的操作。
4. 某调用明确被沙盒拒绝时，仅在宿主提供允许的执行方式且已获授权后，以同一绑定重试一次。`doctor --storage` 已返回具体失败步骤时不再重复执行诊断；在执行权限实际变化后才重试。仍失败就保留原 profile，给出一个完整原任务命令供本机终端执行，或交客户端支持处理。不要在循环中换 shell、改名文件、换凭证目录、重新登录或不断申请放开沙盒。

把宿主弹窗、文件策略错误和 IAM 登录/业务权限分别说明。截图中的“文件删除前询问”是宿主命令安全规则；CLI 或 Skill 不能覆盖它。将 rm 包装成脚本或藏进其他命令以避免检测属于规避规则，不能作为解决办法。

## 存储故障停止条件

正常权限位、目录内存在 .tmp* 或 .writetest 都不能确定根因。CLI 不因这些无关文件拒绝整个存储。使用 CLI 返回的 area/stage/reason/osCode，并记录本次实际执行环境。

若 CLI 诊断也在 atomic_replace 或 delete 被拒绝，停止进一步文件实验。清理失败时只记录 CLI 返回的准确诊断文件路径；不自动删除历史 t1、t2、.writetest 或 .tmp*。需要清理时交用户或客户端支持在有权限的终端确认所属进程已结束，再处理明确文件。

此类阻塞回复可写：“本地保存被当前执行环境拒绝，查询尚未完成。需要允许 dt-cli 在自身配置目录保存和替换文件。请在客户端授权入口确认；如果该客户端不能允许这些操作，请在本机终端执行下面这一条命令。”只提供有证据的宿主选项，不编造 WorkBuddy 设置名称，不承诺一次授权后永远不弹窗。
